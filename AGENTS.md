# Project guidance

- This is the Qollab x IonQ Quantum Impact ambulance-base placement hackathon project. Read `README.md` for current status, `Idea.pdf` for the original Spanish pitch, and `baseline.py` for the original prototype. Input-driven modules are in `ambulance/`; read `docs/CONTRACT.md` and `docs/LOCAL_VALIDATION.md` before integrating them.
- The repository has a minimal Qollab JS/Qiskit shell (`index.html`, `main.js`, `main.css`) and reusable `ui/` modules; read `docs/UI.md`. `python -m tools.preview_ui` is a localhost QA harness, not a production backend. Actual Qollab browser/lifecycle and IonQ remote checks are pending. Coordinate further architecture/services with the team.
- Keep prototype results separate from app capabilities. `baseline.py` uses synthetic population/coordinates, Euclidean coverage, local statevector optimization, and local `StatevectorSampler` sampling; it does not run on IonQ hardware.
- Preserve the distinction between the pairwise quadratic QAOA cost approximation and actual union-of-zones population coverage. Compare final selections using actual coverage and retain greedy/exact baselines for small instances.
- The Dicke initial state and XY mixer maintain exactly `K` selected sites; preserve that constraint if changing the circuit. Site indices in printed results are zero-based; Qiskit bitstrings are reversed when mapped to site indices.
- Be precise about claims: the pitch's 8-site example demonstrates solution quality and sampling probability, not a proven quantum speedup. Avoid representing a simple distance-radius model as actual emergency response time.
- Dependencies are Python with Qiskit 2.5.2, NumPy, and SciPy (`requirements.txt`). Run `python -m unittest discover -s tests -v` for the local core/adapter suite and `python baseline.py` for the original prototype regression. The suite submits no remote jobs; `docs/TESTING.md` lists what it covers. CI (`.github/workflows/tests.yml`) runs the Python suite, `npm test` and the `baseline.py` regression on every PR.
- Run `npm test` for UI controller/model tests. `tests/browser_ui.py` uses Playwright and installed Chrome/Chromium against the real local Python bridge; see `docs/UI.md`. Never use the local HTTP transport in Qollab, which has no external job API or persistent browser storage.
